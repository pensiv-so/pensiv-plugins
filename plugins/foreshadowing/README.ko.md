# 복선

문장에 복선을 심고 회수 지점을 표시해, 아직 회수하지 않은 복선을 한눈에 봅니다.

## 기능

- 문장을 선택하고 플로팅 툴바(또는 우클릭 메뉴)에서 **복선 심기**
- 회수되는 문장을 선택하고 **복선 회수** → 미회수 복선 중 하나를 고르면 그 자리에
  회수 지점이 표시됩니다
- 같은 목록(미회수 먼저, 회수한 것은 취소선)을 **문서 사이드 패널**과 플러그인
  **설정 페이지**에서
- 행을 누르면 해당 문장으로 바로 이동 — 지금 열린 문서가 아니어도 됩니다
- 체크박스는 양방향: 지면 밖에서 회수했다면 수동으로 체크, 회수한 복선의 체크를
  풀면 본문은 그대로 둔 채 다시 미회수 목록으로 돌아갑니다
- 설정 → 분석에 회수율 카드, 미회수 복선이 남은 파일 순위까지
- 한국어·일본어·영어 지원

## 사용법

문서를 열고 복선을 심을 문장을 선택하면 뜨는 툴바에서 북마크 버튼을 누르세요. 해당
문장에 점선 밑줄이 생기고 **복선** 목록에 나타납니다.

본문 옆에서는 문서 헤더의 사이드 패널 토글로 목록을 엽니다 — 기본은 원고 전체,
**이 문서** 탭으로 좁혀 볼 수 있습니다. 문서를 열지 않았을 때는 플러그인 설정
페이지에서 같은 목록을 볼 수 있습니다.

나중에 — 같은 문서든 스무 챕터 뒤든 — 회수되는 문장을 선택하고 같은 툴바에서
**복선 회수**를 누르세요. 선택한 문장과 아직 미회수인 복선 목록이 뜨고, 하나를 고르면
그 자리에 회수 지점이 표시됩니다. 행이 회수 상태로 넘어가고 회수율이 올라가며 —
나중에 체크를 풀면 본문은 그대로 둔 채 다시 미회수로 돌아갑니다.

복선 표시는 **문서 안에** 저장됩니다. 그래서 원고를 고쳐 써도 위치가 따라오고,
본문과 함께 다른 기기로 동기화되며, 버전 기록에도 남습니다. 문장을 지우면 복선도
같이 사라집니다.

## 플러그인 개발자용

**본문에 플러그인 데이터를 고정(anchor)하는 법**의 레퍼런스 예제입니다.

```bash
# 모노레포 루트에서
npm install
npm run build -w @pensiv-plugins/foreshadowing
node scripts/pack-plugin.mjs plugins/foreshadowing   # → foreshadowing.pnsv-plugin
```

### 마크 자체가 데이터베이스

떠올리기 쉬운 설계 — `app.storage`에 `{ fileId, from, to }` 행을 쌓는 방식 — 은
틀렸고, 대가도 큽니다. 위쪽에 한 글자만 입력해도 그 오프셋은 어긋나는데 플러그인은
그 편집을 볼 수 없습니다. [`mark.ts`](src/mark.ts)는 대신 각 복선을 TipTap 마크로
저장합니다. 그러면 앱이 이미 가진 기능이 전부 따라옵니다 — 텍스트와 함께 이동하고,
문서와 같은 경로로 동기화되고, 버전 기록에 들어가고, 표시한 문장을 지우면 함께
사라집니다.

호스트의 인라인 댓글 마크에서 그대로 가져온 옵션: `inclusive: false`(가장자리 입력이
복선을 넓히지 않음), `excludes: ''`(복선끼리 겹칠 수 있음), `keepOnSplit: true`
(복선 안에서 Enter를 눌러도 사라지지 않음).

`app.storage`에 남는 것은 수동 체크와 환경설정 둘뿐이고, 왜 그 둘만은 마크가 될 수
없는지는 [`store.ts`](src/store.ts)에 적혀 있습니다.

### `getSelection()` 말고 `target.range`

두 에디터 서피스 모두 **서피스가 열린 시점에** 스냅샷한 `target.range`를 넘겨줍니다.

```ts
this.registerSurfaceItem({
  surface: 'editor.selection', // 플로팅 툴바 — 폰·태블릿에도 존재
  id: 'plant',
  label: '복선 심기',
  icon: 'Bookmark',
  when: (ctx) => !!ctx.target?.range,
  onClick: (ctx) => {
    const id = crypto.randomUUID();
    this.app.editor.runCommand(
      'setForeshadowAnchor',
      { fid: id, gid: id, kind: 'setup', label: '' },
      ctx.target!.range // ← 사용자가 실제로 선택한 범위
    );
  }
});
```

`onClick` 안에서 `app.editor.getSelection()`을 부르면 메뉴가 포커스를 가져가거나 탭이
커서를 옮긴 *뒤*의 선택을 읽게 되고, 그래서 엉뚱한 단어에 복선이 붙습니다. 데스크톱
우클릭 경로를 위해 같은 항목을 `editor.menu`에도 등록하세요 — 터치에 존재하는 쪽은
`editor.selection`입니다.

`runCommand(name, ...args)`는 플러그인이 자기 에디터 익스텐션에 등록한 커맨드를,
선택 영역만으로는 전달할 수 없는 데이터와 함께 실행하는 방법입니다.

### 원고 전체 읽기

`app.project.content(id)`는 열려 있는 프로젝트의 문서·시트에 대해 `{ doc, text }`를
돌려줍니다. 지금 편집 중인 파일 바깥의 텍스트를 볼 수 있는 유일한 방법이고, 회수율은
여기서 계산됩니다. `doc`은 처음 접근할 때 복제되므로 `text`만 쓰는 스캔은 비용이 없습니다.
[`scan.ts`](src/scan.ts)는 _활성_ 파일만은 에디터에서 직접 읽습니다 — 프로젝트 데이터는
디바운스된 저장만큼 뒤처지기 때문입니다.

`app.ui.openFile(fileId, { range })`가 돌아가는 길입니다. 분할 뷰에서 파일을 열고,
그 에디터가 로드된 뒤 해당 구간으로 스크롤합니다. 파일이 이미 열려 있었는지는
상관없습니다.

### 파일 구성

| 파일                           | 내용                                               |
| ------------------------------ | -------------------------------------------------- |
| [`mark.ts`](src/mark.ts)       | TipTap 마크와 커맨드(앵커 레이어)                  |
| [`anchors.ts`](src/anchors.ts) | 순수 함수: ProseMirror JSON → 복선 → 스레드 → 통계 |
| [`scan.ts`](src/scan.ts)       | `app.project.content()` 기반 프로젝트 전체 스캔    |
| [`store.ts`](src/store.ts)     | 수동 체크와 환경설정(`app.storage`)                |
| [`list.tsx`](src/list.tsx)     | 목록 컴포넌트 하나 — 탭·사이드 패널·설정이 공유    |
| [`main.tsx`](src/main.tsx)     | 등록: 익스텐션·서피스·패널·커맨드·분석·설정        |

위치 계산은 전부 `anchors.ts`에 있고 단위 테스트가 붙어 있습니다
([`test/anchors.test.ts`](test/anchors.test.ts)). `getText()` 오프셋은 ProseMirror
위치가 **아니며**, 그 차이는 두 번째 문단부터 드러납니다.
