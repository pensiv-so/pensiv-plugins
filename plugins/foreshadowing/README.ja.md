# 伏線

文に伏線を置き、回収した箇所を印して、まだ回収していない伏線を一覧します。

## 機能

- 文を選択し、フローティングツールバー（または右クリックメニュー）から **伏線を置く**
- 回収する文を選択して **伏線を回収** → 未回収の伏線から一つ選ぶと、その場所が回収
  箇所として印されます
- 同じ一覧（未回収が先、回収済みは取り消し線）を **ドキュメントのサイドパネル** と
  プラグインの**設定ページ**で
- 行をタップするとその文へジャンプ — いま開いているファイルでなくても可
- チェックボックスは双方向: 紙面の外で回収した伏線は手動でチェックでき、回収済みの
  チェックを外せば本文はそのままに未回収へ戻ります
- 設定 → 分析に回収率カード。未回収が残っているファイルの順位つき
- 日本語・韓国語・英語に対応

## 使い方

ドキュメントを開き、伏線を置く文を選択すると現れるツールバーのブックマークボタンを押します。
その文に点線の下線がつき、**伏線** の一覧に表示されます。

本文の横では、ドキュメントヘッダーのサイドパネル切り替えから一覧を開きます —
既定は原稿全体で、**このファイル** タブで絞り込めます。ドキュメントを開いていない
ときは、プラグインの設定ページで同じ一覧を確認できます。

あとで — 同じドキュメントでも二十章先でも — 回収する文を選び、同じツールバーの
**伏線を回収** を押します。選択した文と未回収の伏線一覧が表示され、一つ選ぶとその場所が
回収箇所として印されます。行が回収済みに移り、回収率が上がり — あとでチェックを外せば
本文はそのままに未回収へ戻ります。

伏線の印は **ドキュメントの中** に保存されます。書き直しても位置が追従し、本文と
一緒に他の端末へ同期され、バージョン履歴にも残ります。文を削除すれば伏線も一緒に
消えます。

## プラグイン開発者向け

**本文にプラグインのデータを固定（アンカー）する** リファレンス例です。

```bash
# モノレポのルートで
npm install
npm run build -w @pensiv-plugins/foreshadowing
node scripts/pack-plugin.mjs plugins/foreshadowing   # → foreshadowing.pnsv-plugin
```

### マーク自体がデータベース

思いつきやすい設計 — `app.storage` に `{ fileId, from, to }` の行を貯める方法 — は
間違いで、代償も大きい。上に一文字入力しただけでそのオフセットはずれますが、プラグインは
その編集を見られません。[`mark.ts`](src/mark.ts) は代わりに各伏線を TipTap のマークとして
保存します。するとアプリが既に持つ仕組みがそのまま効きます — テキストと一緒に動き、
ドキュメントと同じ経路で同期され、バージョン履歴に入り、印した文を消せば一緒に消えます。

ホストのインラインコメント用マークから踏襲したオプション: `inclusive: false`（端での入力が
伏線を広げない）、`excludes: ''`（伏線同士が重なれる）、`keepOnSplit: true`（伏線の中で
Enter を押しても壊れない）。

`app.storage` に残るのは手動チェックと設定の二つだけで、なぜその二つだけはマークに
できないのかは [`store.ts`](src/store.ts) に書いてあります。

### `getSelection()` ではなく `target.range`

どちらのエディタサーフェスも、**サーフェスが開いた時点で** スナップショットした
`target.range` を渡します。

```ts
this.registerSurfaceItem({
  surface: 'editor.selection', // フローティングツールバー — スマホ・タブレットにも存在
  id: 'plant',
  label: '伏線を置く',
  icon: 'Bookmark',
  when: (ctx) => !!ctx.target?.range,
  onClick: (ctx) => {
    const id = crypto.randomUUID();
    this.app.editor.runCommand(
      'setForeshadowAnchor',
      { fid: id, gid: id, kind: 'setup', label: '' },
      ctx.target!.range // ← ユーザーが実際に選んだ範囲
    );
  }
});
```

`onClick` の中で `app.editor.getSelection()` を呼ぶと、メニューがフォーカスを奪った
_あと_、あるいはタップがキャレットを動かした _あと_ の選択を読むことになり、見当違いの
語に伏線がつきます。デスクトップの右クリック経路のために同じ項目を `editor.menu` にも
登録してください — タッチに存在するのは `editor.selection` です。

`runCommand(name, ...args)` は、自分のエディタ拡張が登録したコマンドを、選択範囲だけでは
渡せないデータとともに実行する方法です。

### 原稿全体を読む

`app.project.content(id)` は開いているプロジェクトのドキュメント・シートについて
`{ doc, text }` を返します。編集中のファイル以外のテキストを見る唯一の手段で、回収率は
ここから計算しています。`doc` は初回アクセス時に複製されるので、`text` だけを使う走査に
コストはかかりません。[`scan.ts`](src/scan.ts) は _アクティブな_ ファイルだけエディタから
直接読みます — プロジェクトデータはデバウンスされた保存のぶんだけ遅れるからです。

戻り道は `app.ui.openFile(fileId, { range })` です。分割ビューでファイルを開き、その
エディタが読み込まれてから該当箇所へスクロールします。ファイルが既に開いていたかどうかは
問いません。

### ファイル構成

| ファイル                       | 内容                                                 |
| ------------------------------ | ---------------------------------------------------- |
| [`mark.ts`](src/mark.ts)       | TipTap マークとコマンド（アンカー層）                |
| [`anchors.ts`](src/anchors.ts) | 純粋関数: ProseMirror JSON → 伏線 → スレッド → 統計  |
| [`scan.ts`](src/scan.ts)       | `app.project.content()` によるプロジェクト全体の走査 |
| [`store.ts`](src/store.ts)     | 手動チェックと設定（`app.storage`）                  |
| [`list.tsx`](src/list.tsx)     | 一つのリスト実装 — サイドパネルとシートで共用        |
| [`main.tsx`](src/main.tsx)     | 登録: 拡張・サーフェス・パネル・コマンド・分析・設定 |

位置計算はすべて `anchors.ts` にあり、ユニットテストがついています
([`test/anchors.test.ts`](test/anchors.test.ts))。`getText()` のオフセットは ProseMirror
の位置では **なく**、その差は二段落目から現れます。
